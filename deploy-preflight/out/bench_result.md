# 压测结果（本机实跑）

口径：stub 每 token 20ms、单机同时计算上限 4，超出排队；客户端本机回环。

| 并发 | 首包 P50 | 首包 P95 | 完成 P95 | 成功率 | 吞吐 |
|---|---|---|---|---|---|
| 1 | 3 ms | 3 ms | 3418 ms | 100.0% | 0.29 req/s |
| 2 | 1 ms | 2 ms | 3460 ms | 100.0% | 0.58 req/s |
| 4 | 2 ms | 2 ms | 3405 ms | 100.0% | 1.17 req/s |
| 8 | 3341 ms | 3412 ms | 6885 ms | 100.0% | 1.16 req/s |
| 16 | 6925 ms | 10374 ms | 13773 ms | 100.0% | 1.15 req/s |

**能读出什么**：并发 ≤4 时首包 P95 最低 2 ms（含本机抖动）、吞吐峰值 1.17 req/s；并发超过 4 后首包 P95 抬到 3412 ms、吞吐不再增长（停在 1.16 req/s 附近）——这条曲线就是「该加机器」的依据，也是跟客户谈容量时唯一可信的口径。

**不能读出什么**：不能推断真模型吞吐；不能推断客户机器性能；stub 不含 prefill/decode 差异。
