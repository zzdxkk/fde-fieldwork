## 二、选型结论

| 项 | 选择 | 依据 |
|---|---|---|
| 推理框架 | llama.cpp 原生 | 无容器，走原生二进制，脚本需手写 |
| 模型 | Qwen2.5-3B-Instruct（Q4） | Qwen2.5-7B/3B 为 Apache-2.0，可商用；72B 及以上为社区许可，须法务确认 |
| 容器 | 无（原生安装） | 离线交付用 docker save/load，镜像体积需提前告知客户 |
| 网络 | 全程离线 | 权重、镜像、wheel 三样缺一不可 |

## 四、离线交付清单（按体积排序，先解决运输问题）

- 模型权重（约 4.7GB / Q4 7B）+ sha256 校验和
- Docker 镜像 tar（含推理框架，约 6–12GB）
- Python 依赖 wheel 目录（vLLM 系依赖较重，务必全量）
- docker-compose.yml + run.sh + 回滚脚本
- 部署手册 / 运维手册 / 验收清单 / 培训大纲
- bench.py 与验收用例（客户可自证）

## 五、授权与合规（政企必查，别等法务来问）

- 模型许可：Qwen2.5-7B/3B 为 Apache-2.0（可商用、可修改）；≥72B 版本为 Qwen 社区许可，商用需法务确认。
- 版本锁定：交付时固定模型版本 + 权重 sha256，禁止现场 `ollama pull latest`。
- 数据不出域：推理全在内网；如启用日志，须默认脱敏（手机号/身份证/工单号）。
- 等保相关：审计日志留存 ≥6 个月、账号权限分离、传输加密，这三条客户一定会问。

## 六、降级路径（按代价从小到大）

- 降上下文：8K → 4K，显存/内存吃紧时第一步
- 重量化：FP16 → AWQ 4bit → Q4_K_M，精度损失需抽样对比
- 换小模型：7B → 3B，能力下降要在验收用例上量化，不能口头说「差不多」
- 限并发 + 排队 + 首包提示：宁可慢，不要超时雪崩
- 兜底：模型服务不可用 → 静态 FAQ + 转人工，业务不断流

## 七、本工具不做什么（边界）

- 不做模型效果评测：效果要在客户业务用例上测，不是跑分。
- 不承诺性能：没有 bench 数据就不写数字。
- 不做安全加固全包：等保整改需客户安全团队参与，本工具只给清单。
