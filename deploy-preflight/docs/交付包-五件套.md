# 大模型私有化部署工程包（环境体检 + 方案生成 + 容量估算）

**一句话价值**：到客户机房先跑一遍体检，5 分钟出一份「能不能装、装哪个模型、什么并发、怎么降级」的方案。

**目标客户**：客户 IT 负责人 / 项目经理 / 售前

## 一、实施方案

现场痛点：售前拍胸脯说能跑，实施到场发现没 GPU、没 Docker、磁盘不够，方案全推翻。

方案核心：实测 CPU/内存/磁盘/Docker/GPU → 自动选 vLLM 或 Ollama 量化 → 生成 compose → 出容量估算与降级路径。

节奏：第 1 周场景确认 → 第 2 周原型跑通 → 第 3 周部署+文档 → 第 4 周培训+验收。

## 二、验收清单

1. 运行 app/check_env.py，输出 out/env_report.md 与 deploy/docker-compose.yml
2. 报告须含 6 项实测值与环境判定
3. 无 GPU 时自动降级为 CPU 量化方案，并写明代价
4. 容量表明确标注估算，不冒充实测

## 三、度量表

| 指标 | 人工基线 | 本方案 | 结论 |
|---|---|---|---|
| 体检项 | 凭经验 3–4 项 | 11 项实测（含 GPU 透传、CUDA 版本、时间同步） | 可留痕 |
| 压测 | 口头承诺 | 5 档并发实测，拐点 = 4 并发 | 有据可依 |
| 性能数字 | 拍数字 | 只写跑过的，未跑写「未实测」 | 不造假 |
| 离线清单 | 临时手写 | 6 项 + compose 骨架 | 可复用 |

## 四、培训大纲

| 模块 | 内容 | 学员产出 |
|---|---|---|
| 模块 1（20 分钟） | 体检报告怎么读：哪三项决定方案 | 能自己判断该走哪条路线 |
| 模块 2（20 分钟） | 离线交付：镜像、权重、依赖怎么打包 | 能列出完整离线清单 |
| 模块 3（20 分钟） | 压测与验收：并发、首 token、超时 | 能对客户解释数字口径 |
| 模块 4（15 分钟） | 故障与回滚：服务挂了怎么切 | 有回滚脚本 |

## 五、故障演练表

| 异常场景 | 处理与降级 | 预期结果 |
|---|---|---|
| 客户机房无外网 | 镜像 docker save/load + 依赖 wheel 目录 | 断网可装 |
| GPU 显存不足 | 降上下文 + 量化，必要时切 3B 小模型 | 能跑起来，性能降级写清楚 |
| 并发打满、响应超时 | 排队 + 首 token 提示 + 超时转人工 | 不雪崩 |
| 模型服务崩溃 | 健康检查 + 自动重启 + 静态 FAQ 兜底 | 业务不中断 |

## 六、口头汇报（30 秒）

> 这是我做的大模型私有化部署工程包（环境体检 + 方案生成 + 容量估算）。客户原来凭经验 3–4 项，现在是11 项实测（含 GPU 透传、CUDA 版本、时间同步）。实施方案、操作手册、验收清单、培训大纲、故障演练都写完了，代码在没网的机器上能跑。
