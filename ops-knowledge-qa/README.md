# 设备运维知识库问答（内网离线）

工厂设备科的老师傅会把经验写在交接本上，新人问"空压机压力上不去怎么办"，答案散在三个文档和一个人的脑子里。这个原型把这类问答搬进内网，断网也能用。

## 重点不在"能答"，在"知道什么时候不答"

检索用 BM25，加两道闸门：

1. 分数阈值 —— 最高分不够，直接不算命中；
2. 实词重合 —— 问题里的实词在命中的片段里必须出现，防止同义但主题错位。

再配两条硬规则：答案必须带引用出处；没依据就回复"知识库未覆盖，转人工"，涉电、涉消防的问题额外给安全指引。

## 三段切分，数字不好看的那一段才是真的

| 集合 | 用途 | 命中率 |
|---|---|---|
| dev | 只在这里调阈值 | 81.8% |
| test | 验证"补同义词"这类改写是否有效，**不能当泛化能力** | 100% |
| final | 3 条从未参与调参，只跑一次 | 33.3% |

final 的 33.3% 是真实的冷启动值：3 条里只对 1 条。补 15 组同义词后 test 从 40% 升到 100%，说明**词表比模型重要**——这是现场最该先做的事。

域外问题 3/3 正确拒答，0 条误答。

## 跑

```bash
python3 app/main.py     # 报告写到 out/report.md
```

`app/data/kb.csv` 是知识条目，`app/data/questions.csv` 是带切分标记的问题集（dev / test / final）。

## 已知问题

- BM25 不懂"压力上不去"和"打不上压"是一回事，靠同义词表补，词表要每周从真实提问里加。
- 只覆盖 12 条知识条目，条目过千后要换成向量检索，届时阈值含义会变，必须重测。
- 没接真实工单系统，转人工是打印一句话，不是派单。
