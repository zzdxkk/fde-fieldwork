# 合同 / 采购材料一致性核查

20 份合同、7 条条款规则，0.02 秒筛完，把"哪条超限、超多少、怎么改"逐条指出来。合同是设备采购类，服务与框架合同阈值不同，本版只覆盖设备类。

## 为什么需要分级

如果一半合同都报"高风险"，业务部门第二次就不看了。所以做了两件事：

1. **语境豁免**：有履约保函的预付比例降为中；金额小于 10 万的小额采购，质保条款降为低。
2. **金额门槛**：必须整改项 ≥2 条、或单条且金额 ≥50 万，才判高。

高风险占比从 50% 降到 30%，每一次降级都留记录，可以被法务推翻、也可以被审计追溯。

## PDF 抽取是自写的

`app/pdf_extract.py` 用标准库 zlib + ASCII85 解码，再解析 Tj/TJ 文本操作符，不依赖 pdfplumber。

- 字段级准确率 96.3%（27 个字段中 26 个）
- 失败的那 1 个字段如实列在报告里：C 合同的字段名写成 `warranty_month` 少了 s，抽取不到就报缺失，不猜。

## 跑

```bash
python3 app/main.py        # 报告写到 out/report.md
```

首次运行若 `out/pdfs/` 为空，会自动生成三份样例合同。造这三份 PDF 需要 `reportlab`（`pip install reportlab`），解析本身不依赖它：没装库时报告会直接写"PDF 抽取未执行"，测试里跳过那 2 个造 PDF 的用例，不会假装跑过。`app/data/contracts.csv` 是与这三份合同对应的真值表。

## 已知问题

- 不做扫描件 OCR：图片型 PDF 要先走 OCR，那是另一摊工程量，接进来之前不承诺"什么合同都能读"。
- 不做自动签署拦截：工具出清单，签字权在人。
- 阈值逐条标了来源，没有法务确认的写"待确认"，不把经验值冒充制度。
